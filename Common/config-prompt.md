**Роль:** Системный архитектор / IoT-разработчик.

**Контекст:** Мы разрабатываем прототип SCADA-системы (стек: Python, React, PostgreSQL). В системе есть два основных компонента, работающих с Modbus:

1. **Эмулятор Modbus-сервера** (имитирует работу физических модулей ввода-вывода).
2. **Утилита опроса** (Backend), которая читает данные с эмулятора (или реальных устройств), сохраняет их в БД и передает в UI.

**Задача:** Разработать единый, унифицированный формат конфигурации (JSON), который будет служить источником истины (Single Source of Truth) как для эмулятора (чтобы знать, какие регистры создать и как имитировать физические процессы), так и для Backend-утилиты (чтобы знать, куда подключаться, какие регистры опрашивать и как их интерпретировать).

**Требования к структуре конфигурации:**

1. **Уровень устройства (Device):**
* **Идентификатор устройства:** Уникальное имя или ID.
* **Тип подключения:** Поддержка параметров для Modbus TCP (IP, Port) и Modbus RTU (Port/COM, Baudrate, Parity, Data bits, Stop bits).
* **Modbus Address:** Идентификатор устройства на шине (Unit ID / Slave ID).


2. **Уровень каналов ввода-вывода (IO Ports/Channels):**
* **Уникальный ID канала:** Обязательный строковый идентификатор канала (может назначаться пользователем или генерироваться автоматически, например `pump_1_status` или `ai_channel_01`).
* **Тип порта и физические диапазоны:**
* **DI (Digital Input):** Принимает значения 0/1.
* **DO (Digital Output):** Принимает значения 0/1.
* **AI (Analog Input):** Принимает значения в заданном диапазоне (например, напряжение 0..12V, 0..24V, либо ток 4..20mA). Диапазон должен описываться в конфигурации (min_val, max_val).




3. **Уровень Modbus-маппинга:**
* У каждого канала должна быть явная привязка к типу регистра (Coils, Discrete Inputs, Input Registers, Holding Registers) и его адресу (offset).
* Привязка по умолчанию: DI -> Discrete Inputs, DO -> Coils, сырые значения AI -> Input Registers.
* **Коэффициенты для Analog Input (AI):** Для аналоговых датчиков эмулятор и backend должны поддерживать линейное преобразование $y = kx + b$. Коэффициенты $k$ и $b$ должны храниться в **Holding Registers**. Конфигурация канала AI должна явно указывать Modbus-адреса, по которым лежат значения $k$ и $b$ для данного конкретного канала.
